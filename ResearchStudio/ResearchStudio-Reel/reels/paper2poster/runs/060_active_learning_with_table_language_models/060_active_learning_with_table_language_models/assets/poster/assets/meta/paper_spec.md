## Problem
**Necessary:** Fine-tuning tabular language models for industrial tasks needs many labels, but only experts can annotate the highly technical, domain-specific spreadsheet tables, making label acquisition prohibitively expensive.
**Additional:** Sub-cell named entity recognition on tables is a novel *nested multi-instance* problem: each table holds many cells, and each cell carries multiple token labels, so it is unclear whether to acquire at the token, cell, or table level.
**Audio script:** Industry runs on spreadsheets. Plant operators track equipment, sensors, and vessels in loosely structured tables, and extracting that information automatically requires fine-tuning tabular language models on labeled examples. The catch is cost: these tables use highly technical, domain-specific language that only a handful of experts can annotate, so acquiring enough labels quickly becomes prohibitively expensive. The paper frames this as a sub-cell named entity recognition task and observes that it is a genuinely new kind of active learning problem, because each table contains many cells and each cell contains multiple token-level labels at once.

## Motivation
**Necessary:** Settings with abundant unlabeled data and costly expert labels are a natural fit for active learning, yet no prior work combines active learning with tabular language models.
**Additional:** Large transformers require batch-based acquisition (not one-by-one selection) and train for multiple epochs per round, so naive uncertainty sampling picks highly correlated, redundant cells that add little value.
**Audio script:** Active learning is built exactly for situations with plentiful unlabeled data and expensive labels: it tries to squeeze the most model performance out of every annotation. But large transformer models can't be updated one example at a time; they need batches trained over several epochs, which means the acquisition function must pick a whole batch at once. Pure uncertainty sampling tends to grab very similar, correlated cells, often from the same table or even the same row, wasting the annotation budget. Despite this obvious fit, the authors point out that no one had yet studied active learning together with tabular language models, which is the gap they set out to fill.

## Contribution
**Necessary:** The paper presents the first industrial NER use case pairing tabular language models with active learning, outlines the novel problems tabular data raises for active learning, and adapts well-known acquisition functions to tables with an empirical evaluation on a real-world dataset.
**Additional:** It argues that a cell-level acquisition function is sufficient because the tabular language model already encodes full-table context, avoiding the need for a separate hierarchical table-then-cell selection.
**Audio script:** The work makes three contributions. First, it introduces a concrete industrial use case that pairs tabular language models with active learning for sub-cell entity extraction. Second, it lays out the new problems that tabular data creates for active learning, in particular the nested multi-instance structure and the question of which granularity to acquire at. Third, it adapts several well-known acquisition functions to the table setting and evaluates them empirically on a genuine industrial dataset. A key design argument is that acquiring at the cell level is enough, because the model's table-biased encoder already makes every cell aware of its full-table context.

## Method
**Necessary:** A table-biased transformer encoder (using a row-column visibility matrix and within-cell positional encoding) produces context-sensitive token representations, and a classification decoder assigns IO NER tags over the entity types TAG, EQ, QUANT, and UoM. Pool-based active learning then iteratively selects batches of the most informative cells for an oracle to label.
**Additional:** Four cell-level acquisition functions are compared: MNLP (pure uncertainty via maximized normalized log-probability), MNLP+ (MNLP plus a forced round-robin maximum-table-diversity constraint), BADGE (k-MEANS++ over per-cell gradient embeddings for batch diversity), and Rand (uniform random cells) as a baseline.
**Key equation:** `$\arg\min_{X_S}\ \mathbb{E}_{x\sim P}\left[\ell(f_\theta(x), y)\right]$` ; `$f_{acq}^{MNLP}(c_{i,j};f_\theta)=\frac{1}{t}\sum_{z=1}^{t}\log y^{*}_{i,j,z}$` ; `$f_{acq}^{BADGE}(c_{i,j};f_\theta)=\text{k-MEANS++}\!\left(\frac{1}{t}\sum_z g_{i,j,z}\right)$`
**Audio script:** The model is a tabular language model: a transformer encoder that replaces vanilla attention with a row-column visibility matrix and uses within-cell positional encoding, so each token gets a representation aware of the whole table. A classification decoder then labels every token with IO tags over four entity types: equipment tags, equipment names, physical quantities, and units of measurement. On top of this sits pool-based active learning, which repeatedly picks a batch of the most informative cells for an expert oracle to label. The authors compare four acquisition functions. MNLP scores cells by their normalized log-probability uncertainty. MNLP+ adds a forced round-robin across tables to maximize table diversity. BADGE clusters per-cell gradient embeddings with k-means++ to get a batch that is both uncertain and diverse. And Rand simply samples cells uniformly at random as a baseline.

## Dataset / Benchmark
**Necessary:** A real-world industrial dataset of downsampled spreadsheets from multiple plants (max 5 rows per table), expert-annotated cell-by-cell with prodi.gy; a random split yields 55 training tables and 24 test tables.
**Additional:** The 55 training tables hold 4,774 cells but only 1,112 NER span labels (0.23 labels per cell), so roughly 77% of cells contain only O-tagged tokens, an extreme class imbalance typical of industrial settings.
**Audio script:** The evaluation uses a real industrial dataset, not an academic benchmark. Spreadsheets from several plants were downsampled so that each table had at most five rows, and expert annotators labeled every cell using the prodi.gy span-based annotation tool. After a random train-test split, there are 55 tables for training and 24 for testing. The training set contains 4,774 cells but only about 1,100 entity labels, which works out to just 0.23 labels per cell. That means roughly 77 percent of cells contain no entity at all, an extreme class imbalance that the authors note is very typical of real industrial data.

## Key Result
**Necessary:** BADGE is the only acquisition function that clearly beats random selection and even exceeds full-training performance, reaching the ceiling with far fewer labels; MNLP only slightly edges Rand after about 500 labels.
**Additional:** MNLP+ (forced maximum table diversity) is by far the worst, showing that over-enforcing table diversity is detrimental; MNLP also shows higher variance, indicating greater sensitivity to the initial seed in this high-imbalance regime.
**Audio script:** The central result is measured by micro-averaged F1 on the held-out test set across active learning iterations. BADGE, the batch-diverse gradient method, is the standout: it clearly outperforms random selection and even surpasses the ceiling set by training on the full dataset, all while using far fewer labels. Pure uncertainty sampling with MNLP is disappointing, only pulling slightly ahead of random after around 500 labels, and with noticeably higher variance that signals sensitivity to the initial seed. Most striking, the MNLP+ variant that forces maximum table diversity is the worst of all, showing that pushing diversity too hard actively hurts.

## Ablation Study
**Necessary:** Comparing MNLP, MNLP+, BADGE, and Rand isolates the effect of diversity: built-in batch diversity (BADGE) helps, while forced maximum table diversity (MNLP+) is detrimental, dropping well below the random baseline.
**Additional:** A table-diversity metric (number of distinct tables sampled per iteration) shows MNLP fixates on few tables, MNLP+ spreads across as many tables as the budget allows, and BADGE sits in between, balancing table diversity against cell uncertainty.
**Audio script:** The four acquisition functions effectively ablate the role of diversity. Comparing them shows that the right amount of diversity matters enormously. BADGE's built-in batch diversity is beneficial, but MNLP+'s forced maximum table diversity is harmful, falling below even random sampling. To understand why, the authors track how many distinct tables each method draws cells from at each iteration. MNLP fixates on just a few tables, MNLP+ spreads across as many as the budget permits, and BADGE strikes a balance in the middle. This confirms that the goal is not maximum diversity but a careful trade-off between diversity and per-cell uncertainty.

## Takeaway
**Necessary:** For active learning with tabular language models, cell-level acquisition with built-in batch diversity (BADGE) can hit full-training performance with far fewer expert labels, but forcing maximum table diversity backfires: balancing diversity against uncertainty is the key.
**Additional:** This is the first study of active learning for tabular language models, leaving open questions about computational efficiency and the burden that table-diverse acquisition places on human annotators.
**Audio script:** The lasting message is that active learning really can slash the expert-labeling cost of tabular language models, but only if diversity is handled with care. Cell-level acquisition that builds in batch diversity, as BADGE does, reaches full-training performance with a fraction of the labels, whereas bluntly forcing maximum table diversity backfires and does worse than random. The winning recipe is to balance diversity against uncertainty rather than maximize either alone. As the first work on this problem, it also flags two open frontiers: the computational cost of table-diverse acquisition, and the extra cognitive load it places on the human annotators who must interpret each new table.
